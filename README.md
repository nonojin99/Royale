# 로얄 (Royale)

**1v1 실시간 라인 전략 게임.** 덱을 고르고, 엘릭서를 모아 카드를 배치하고, 3분 안에 상대 타워를 더 많이 부수면 승리.

**3개 덱 · 24장 카드** — 방어형(기갑단) / 물량형(군체) / 고효율형(신념단).
서로 다른 덱끼리 붙는 비대칭 매치업이 게임의 깊이를 만든다.

---

## 이 프로젝트의 기술적 핵심

> **상태를 동기화하지 않는다. 입력만 동기화한다.**

유닛 좌표나 HP는 네트워크로 보내지 않는다. 두 클라이언트와 서버가 **완전히 동일한 시뮬레이션**을 각자 독립적으로 돌리고, 오직 `누가 · 몇 번째 틱에 · 어떤 카드를 · 어디에 냈는가`만 주고받는다 (**Deterministic Lockstep**).

경기 하나의 전체 네트워크 트래픽이 **수 KB**다. 대신 대가가 있다 — 시뮬레이션이 1비트라도 어긋나면 두 플레이어는 서로 다른 게임을 하게 된다. 그래서 시뮬레이션 코드는 **부동소수점을 일절 쓰지 않는다.** 모든 좌표·거리·속도가 "밀리타일" 단위 정수다.

```
클라 A ──┐                      ┌── 커맨드 브로드캐스트 ──▶ 클라 A (시뮬 실행)
         ├──▶ 서버 (권위 시뮬) ──┤
클라 B ──┘                      └── 커맨드 브로드캐스트 ──▶ 클라 B (시뮬 실행)
                  ▲
                  └── 매초 상태 해시 대조 → 어긋나면 스냅샷으로 리싱크
```

- **[게임 기획서](docs/GAME_DESIGN.md)** — 아레나, 카드, 엘릭서, 유닛 AI, 밸런스 설계 의도
- **[넷코드 설계](docs/NETCODE.md)** — 시간 모델, 결정론 규칙 5개, 데스싱크 감지, 프로토콜

## 구조

```
packages/
  shared/   결정론 시뮬레이션 — 서버와 클라이언트가 이 코드를 그대로 공유한다
            fixed.ts  고정소수점 정수 수학 (부동소수점 금지)
            rng.ts    시드 PRNG (Math.random 금지)
            arena.ts  지형 / 다리 / 배치 구역
            cards.ts  카드·유닛 데이터 테이블 (밸런싱은 전부 여기서)
            decks.ts  덱 정의 4종 (모듈 로드 시점에 정합성 검증)
            sim.ts    ★ 틱 진행: 타겟팅 · 이동 · 전투 · 승패
  server/   WS 서버 + 룸/매치메이킹 + 권위 시뮬 + 데스싱크 판정 + 연습용 봇
  client/   PixiJS 렌더러 + 클럭 동기화 + 손패 UI + 넷 계기판
```

`shared`는 DOM도 타이머도 참조하지 않는 순수 함수 덩어리다. 그래서 Node와 브라우저에서 **같은 파일**이 돌고, 그게 결정론의 근본 보장이다.

## 실행

```bash
pnpm install
pnpm --filter @royale/shared build   # 클라/서버가 shared의 빌드 결과를 참조한다

# 터미널 2개
pnpm dev:server     # ws://localhost:8787
pnpm dev:client     # http://localhost:5173
```

- 브라우저 2개(또는 시크릿 창)로 열면 서로 매칭된다.
- 혼자 테스트하려면 **`http://localhost:5173/?solo=1`** — 서버가 봇과 즉시 매칭해준다.
- 다른 서버를 가리키려면 `?server=ws://호스트:포트`, 덱을 미리 고르려면 `?deck=steel`

### 조작

- 시작 화면에서 **덱을 고른다** (기갑단 / 군체 / 신념단)
- 하단 손패에서 카드를 고른다 (클릭 또는 숫자키 `1`~`4`)
- **내 진영**을 클릭하면 배치된다. 강 위·상대 진영은 배치 불가
- 상대 공주탑을 부수면 그 레인의 상대 진영에도 배치할 수 있게 된다

### 공중 유닛

`✈` 표시가 붙은 카드는 **강과 다리를 무시하고 직선으로 난다.** 화면에서는 지면에 그림자를 남기고 본체가 떠 있는 것으로 구분된다.

지상 전용 공격(`화염병`, `공성전차`, `술사` 등)은 공중을 때리지 못한다. **덱에 대공 수단이 없으면 상대 공중 유닛에 아무것도 못 하고 진다** — 그래서 모든 덱이 대공 카드를 최소 하나 갖도록 테스트로 고정해두었다.

화면 우하단의 `42ms · tick 291/297 · desync 0` 이 넷 계기판이다.
**`desync`가 0이 아니면 시뮬레이션 코드에 버그가 있다는 뜻이다** — 조용히 넘어가면 안 된다.

## 테스트

```bash
pnpm --filter @royale/shared test      # 결정론 단위 테스트 (31개)
pnpm --filter @royale/server test:e2e  # 실제 서버 + 클라 2개 프로세스로 넷코드 검증
```

E2E는 진짜 서버 프로세스를 띄우고, **서로 다른 덱을 고른** 독립된 두 클라이언트가
카드를 마구 내는 동안 **같은 틱의 상태 해시가 일치하는지**와
**서버가 리싱크를 한 번도 보내지 않았는지**를 확인한다.
비대칭 덱은 양쪽 시뮬이 서로 다른 카드 테이블을 참조한다는 뜻이라, 미러전보다 깨지기 쉽다.

```
▶ 매치 성립 (A=team0, B=team1, 덱=steel vs swarmhive)
tick 400 해시 → A=3424630032 B=3424630032
배치 시도: A=7 B=8 / 리싱크: A=0 B=0
공통 틱 20개에서 해시 전부 일치
✅ E2E 통과
```

## 배포

| 대상 | 플랫폼 | 이유 |
|------|--------|------|
| 서버 | **Fly.io** (`fly.toml`) | WebSocket 지원, 리전 선택으로 지연 관리 |
| 클라이언트 | **GitHub Pages** (Actions) | 정적 파일이면 충분 |

```bash
fly launch --no-deploy
fly deploy
```

GitHub Pages 쪽은 `Settings → Pages → Source: GitHub Actions` 로 켜고,
`Settings → Variables → Actions` 에 `VITE_SERVER_URL = wss://<앱이름>.fly.dev` 를 넣으면 된다.

> GitHub Pages는 정적 호스팅이라 WebSocket 서버를 올릴 수 없다. 서버는 반드시 별도 호스팅이 필요하다.

`auto_stop_machines`를 **끄는 것이 중요하다.** 매치 상태가 프로세스 메모리에 있어서, 머신이 멈추면 진행 중인 경기가 통째로 사라진다.

## 로드맵

| | 내용 | 상태 |
|---|------|------|
| M0 | 모노레포 · 공유 시뮬 · 결정론 테스트 | ✅ |
| M1 | 아레나 · 타워 · 엘릭서 · 유닛 AI | ✅ |
| M2 | WS 서버 · 매치메이킹 · 커맨드 예약/브로드캐스트 | ✅ |
| M3 | PixiJS 클라이언트 · 클럭 동기화 · 데스싱크 계기판 | ✅ |
| M4 | 덱 선택 · 3덱 24장 · 공중/대공 메커니즘 | ✅ |
| M5 | 리플레이 저장 · 자동 대전 밸런싱 도구 · 덱 편집 | ⬜ |
| M6 | 스프라이트 · 이펙트 · 사운드 | ⬜ |
| M7 | 랭킹 · 관전 · 다중 리전 | ⬜ |

리플레이는 이 아키텍처에서 거의 공짜다 — `시드 + 커맨드 목록`만 저장하면 경기 전체가 재현되고, 그 크기가 **수백 바이트**다.

덱이 3개라 매치업은 6개이고, 덱을 늘리면 제곱으로 불어난다. 손으로 밸런싱할 규모가 아니라서, 시뮬이 순수 함수라는 성질을 이용해 **헤드리스 자동 대전으로 승률표를 뽑는 도구**가 M5에 들어간다. 현재 카드 수치는 역할 구조에 맞춘 초기값이지 검증된 밸런스가 아니다.
