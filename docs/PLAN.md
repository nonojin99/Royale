# 완성까지 계획서

현재 상태 기준으로 **무엇이 끝났고 무엇이 남았는지**를 체크박스로 정리한다.
각 항목은 "끝났다고 말할 수 있는 기준"까지 함께 적는다 — 그래야 체크가 의미를 갖는다.

> 갱신 기준일: M6.1(일꾼 경제) 커밋 시점
> 코드 4,400줄 · 결정론 테스트 56개 · E2E 2종 전부 통과

---

## 지금 어디쯤인가

```
기반 ████████████████████ 100%   결정론 시뮬 · 넷코드 · 리플레이
게임 ████████████████░░░░  80%   경제 · 테크 · 전투 · 승패는 동작. 밸런스 미검증
연출 ███████░░░░░░░░░░░░░  35%   스프라이트 배관은 뚫림. 이미지·이펙트·사운드 없음
운영 ██████░░░░░░░░░░░░░░  30%   배포 설정은 있으나 실제 배포·매칭·랭킹 없음
```

**기술적으로 어려운 부분은 이미 넘었다.** 결정론적 lockstep, 데스싱크 감지, 리플레이 재현은 전부 검증된 채로 돌아간다. 남은 것은 대부분 **콘텐츠와 다듬기**이고, 하나씩 붙이면 되는 일이다.

## M7.5 — 맵 개편 (스타크래프트 오마주) 🗺️

지금 맵은 강 하나에 다리 둘인 클래시 로얄식이다. 게임은 이미 일꾼·확장·테크를
가진 매크로 RTS인데 **맵만 CR 잔재로 남아 있다.** 지금 맵이 물을 수 있는 질문은
"어느 다리로 갈까"뿐이고, "어디에 확장하고 어디를 조일까"를 못 묻는다.

- [x] **지형을 데이터로 분리** — `arena.ts`의 `WALLS`, `nav.ts`의 `TERRAIN` 격자
- [x] **결정론적 흐름장 길찾기** — 목적지별 거리장을 한 번만 계산해 캐시.
      유닛당 비용이 상수라 후반 교전에서도 안전하다
- [x] 하드코딩된 다리 경유(`moveGoal`의 레인 방식) 제거
- [x] **24×24 오리지널 맵** — 본진 병목 · 중앙 고지 · 측면 가림막
- [x] 점대칭 자동 생성 — 벽을 절반만 적고 나머지는 코드가 만든다
- [ ] 언덕 개념 — 고지에서 저지를 때릴 때의 사거리 이점
- [ ] 경기 시간·매장량 재조정 (맵이 바뀌면 거리가 바뀐다)
- [ ] 지형 아트 (지금은 회색 사각형)
- [x] **완료 기준**: 맵을 바꾸는 일이 코드가 아니라 데이터를 바꾸는 일이 된다

> **왜 스타 맵을 1:1로 옮기지 않는가**: 게임이 이미 RTS라서, 맵까지 그대로
> 베끼면 오마주가 아니라 카피가 된다. 그리고 실제로 재미도 없다 — 로스트
> 템플은 4인용에 20분 경기, 일꾼 50기를 전제로 만든 비율이라 240초·일꾼 8기인
> 이 게임에 안 맞는다.
>
> 가져올 가치가 있는 건 배치도가 아니라 **문법**이다: 본진(입구 하나) →
> 앞마당 → 다툼 지역 → 중앙 요충지. 이건 RTS 맵 설계의 보편 문법이지
> 스타크래프트의 것이 아니다.
>
> 게다가 이 게임에는 스타에 없는 축이 있다. 유닛이 기지 반경에서만 나오므로
> **기지 자리 사이의 간격**이 "다음 자리로 건너뛸 수 있는가"를 결정한다.
> 앞마당을 본진 배치 반경 바로 밖에 둔 것이 그래서다.

## M8 — 밸런싱 ⚖️

현재 수치는 역할 구조에 맞춘 초기값이지 **검증된 밸런스가 아니다.**

### 8.1 자동 대전 도구
- [ ] 헤드리스 봇 vs 봇 루프 (렌더링 없이 초당 수백 경기)
- [ ] 매치업 6개 × 전략 축(일꾼우선/테크우선/병력우선) 승률표 출력
- [ ] 리플레이 요약 집계 재사용 (이미 유닛·확장·테크를 종류별로 집계 중)
- [ ] **완료 기준**: `pnpm balance` 한 번으로 승률표가 나온다

### 8.2 실측된 구조 문제 — 상세는 [REVIEW.md](./REVIEW.md)

헤드리스 자동 대전으로 측정한 결과, 경기가 두 극단뿐이다:
러시 매치업은 41~88초 본진파괴, 나머지는 300초 무승부.

- [x] **P0-1** 러시/스톨 양극화 — siege 배율 도입, 기갑단 시작 구성 교체.
      무방비 격파 79~96초, 전 매치업 본진파괴 종결(평균 91~110초)
- [x] **P0-2** 연장 판정 — `기지 수 → 연장 → 기지 총 HP → 채굴량` (REPLAY v3).
      무승부 26/60 → 0/60
- [x] **P0-3** 확장 미발화 — 봇 저축 로직 + "곧 고갈" 경고. 확장 8판 24회,
      매크로가 병력전략에 8:0
- [ ] 종족 승률 45~55% 수렴 — steel vs 군체 3:7 남음. 전략형 봇으로 재측정

### 8.3 조정
- [ ] 승률표를 근거로 유닛 수치 조정
- [ ] 조정마다 과거 리플레이 재현 검증 (`pnpm --filter @royale/server replay`)
- [ ] **완료 기준**: 6개 매치업 승률이 모두 45~55%

## 우선순위에 대한 판단

**M7(아트)을 먼저 하는 이유**는 이미지가 이미 생성 중이기 때문만이 아니다. 지금 게임은 **도형이라 재미를 판단할 수 없는 상태**다. 밸런싱(M8)을 아무리 정교하게 해도, 화면에서 무슨 일이 일어나는지 안 보이면 그 수치가 좋은지 나쁜지 감이 오지 않는다. 연출이 먼저 붙어야 밸런싱 판단이 가능해진다.

**M8(밸런싱)은 M7 다음**이 맞다. 자동 대전 도구는 사람 눈과 무관하게 돌지만, 그 결과를 해석하려면 실제로 플레이해본 감각이 있어야 한다.

**M9(사운드)는 M8과 병렬**로 가도 된다. 서로 의존하지 않는다.

**M11(배포)은 M7이 끝나면 바로** 해도 좋다. 남에게 보여줄 수 있는 상태가 되는 시점이 곧 피드백이 들어오기 시작하는 시점이고, 그 피드백이 M8·M10의 우선순위를 정해준다.

## 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| **유닛 수 상한이 없다** | 후반 교전에서 O(n²) 시뮬이 느려지고, 심하면 틱을 놓쳐 데스싱크 | M7.6에서 상한 도입. 인구 개념을 넣는 것도 방법 |
| **리플레이가 재배포 시 소실** | 밸런싱 근거 데이터가 날아감 | M11.2. 볼륨 또는 오브젝트 스토리지 |
| **AI 생성 이미지의 일관성** | 24장이 제각각이면 화면이 조잡해짐 | ART_PIPELINE §3.3의 구도 규격 준수. 크기 등급이 특히 중요 |
| **일꾼이 공격 대상이 아니다** | 일꾼 견제라는 RTS의 큰 축이 빠져 있음 | 의도적 스코프 제외. 넣으려면 일꾼을 시뮬 엔티티로 올려야 함 |
| **모바일 미검증** | 터치 조작이 안 맞을 수 있음 | M10.3 |
