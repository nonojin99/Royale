# 언리얼 PoC 1주 — 침공 모드 프로토타입

**이 문서의 용도**: 오너 로컬 머신의 Claude Code 세션이 **이것만 읽고** UE
프로젝트를 시작할 수 있게 만든 이식 사양서다. 웹판(`pomingpu-royale`)의
시뮬이 실제로 쓰는 값을 스크립트로 뽑아 적었다 — 손으로 옮기면 반드시 틀린다.

**결정 상태 (라운드 49)**: 전환은 **아직 결정되지 않았다.** 오너가 UE를 설치해
돌려 보고 "퀄리티 차이가 심하다"고 판단해, **1주 PoC 후 범위를 정하기로** 했다.
그때까지 웹판은 그대로 살아 있고 아무것도 지우지 않는다.

---

## 0. PoC가 답해야 하는 질문

1주 뒤 이것만 보고 결정한다. **"UE가 예쁘다"는 이미 아는 사실이라 답이 아니다.**

| # | 질문 | 어떻게 판정하나 |
|---|---|---|
| 1 | **파도 방어가 3D에서도 읽히는가** | 화면 하나에서 "어디서 오는지 · 내 병력이 어디 있는지 · 누가 이기고 있는지"가 즉시 보이나. 쿼터뷰 카메라에서 유닛 30~40기가 뭉쳤을 때도 |
| 2 | **밸런스 수치가 3D에서 그대로 성립하는가** | 같은 수치로 1파도가 웹판과 비슷한 난이도인가. 사거리 5타일이 3D에서 "가깝다"로 느껴지면 수치 전체를 다시 잡아야 한다 |
| 3 | **제작 속도가 감당되는가** | 유닛 하나를 세우는 데(모델·애님·머티리얼·AI) 며칠이 드나. 22종이면 그 배수다 |
| 4 | **밸런스를 어떻게 잴 것인가** | 웹판은 864판을 400초에 돌린다. UE에서 수십 판을 헤드리스로 돌릴 길이 보이나. 안 보이면 **밸런스는 웹판에서 잡고 UE는 표현만** 맡는 구조가 된다 |

**4번이 가장 중요하다.** 48라운드가 "실측 기반 결정"으로 굴러온 이유이고,
그 능력을 잃으면 개발 방식 자체가 바뀐다.

## 1. PoC 범위

### 넣는다
- 맵 1장, 48×48 타일 평지 + 절벽 몇 개 (지형 규칙은 §MAP 참조)
- 내 본진 1개 (중앙), 일꾼 채굴, 미네랄 카운터
- 유닛 **3종만**: 소총병 · 화염병 · 공성전차 (근접/원거리/공성 삼각의 최소 집합)
- 파도 스폰 1~6 (모서리 로테이션 포함)
- 유닛 배치(클릭) · 드래그 선택 · 이동 명령
- 쿼터뷰 카메라 (고정 각도, 줌만)

### 안 넣는다 (PoC에서 판단에 기여하지 않는 것)
- 멀티플레이·네트워크 (PvE는 결정론이 **필요 없다** — §2)
- 리플레이·해시 검증
- 드래프트·유물·영웅·능동 스킬
- 런 체인(3무대)·둥지
- 나머지 종족, 나머지 19종 유닛
- 사운드·UI 폴리시

## 2. 결정론 — PoC에서는 **버린다**

웹판의 뼈대는 정수(milli-tile) 결정론 lockstep이다. 그 이유는 **1v1 멀티에서
두 클라이언트가 같은 게임을 봐야 하기 때문**이다.

**침공은 싱글 PvE라 그 이유가 없다.** 서버 권위도, 해시 검증도, 리플레이도
필요 없다. 그러니 UE에서 float를 그냥 써도 된다.

> 이 판단이 UE 전환의 문턱을 크게 낮춘다. 만약 나중에 1v1 대전까지 UE로
> 옮기려 한다면 **그때는 정수 시뮬을 C++로 다시 지어야 하고**, 그건 PoC와
> 전혀 다른 크기의 일이다. PoC 결과로 그것까지 결정하지 말 것.

다만 **고정 타임스텝은 유지**하기를 권한다(20Hz). 프레임 레이트에 따라 전투
결과가 달라지면 수치 비교(질문 2)가 무의미해진다. `FixedTick(0.05s)`을 돌리고
렌더는 보간하는 구조.

## 4. 이식할 때 반드시 지켜야 하는 규칙 (여기서 틀리면 수치가 무의미해진다)

1. **데미지는 고정 정수, 방어력·랜덤 없음.** "몇 방에 죽는가"가 상성의 전부다.
   예: 화염병 100 vs 소총병 220 → 3방. 강화 1단계(+10%)면 120 → **2방**.
   UE에서 랜덤 편차를 넣는 순간 이 설계가 사라진다
2. **공속은 틱 단위다.** 소총병 20틱 = 1초에 1발. 애니메이션 길이가 이걸
   바꾸면 안 된다 — 애님은 공속에 맞춰 재생 속도를 조절할 것
3. **`count`는 한 번 배치할 때 나오는 마리 수다.** 소총병 카드 하나 = 3마리.
   코스트 3은 3마리 값이다
4. **생산 큐가 없다.** 카드를 고르고 땅을 클릭하면 **즉시** 나온다
   (배치 후 `DEPLOY_TICKS`=20틱 = 1초 행동 불가). 건물을 짓고 기다리는
   RTS가 아니다 — 이게 이 게임의 템포다
5. **배치는 기지 반경(9타일) 안에서만.** 그래서 전진 기지가 곧 공격 준비다
6. **침공 채굴은 절반(50%)이다.** 주 수입은 파도 소탕 보상(예산의 70%).
   "버티기만 하면 가난해진다"가 이 모드의 압력이다
7. **고지 방어**: 저지 → 고지 공격은 데미지 70%. 공중은 면제

## 5. 지형 규칙 (웹판 MAP_RULES.md 요약)

- 48×48 그리드. 고도는 **2단계**만 (평지 / 고지)
- 절벽 벽면은 **2타일 두께**로 그려 높이를 읽히게 한다 (라운드 33)
- 램프(경사로)는 고지 진입점이고, **폭이 좁아야 방어 가치가 생긴다**
- 물은 지상 유닛에게 벽, 공중은 통과
- 스폰 모서리: 내 본진에서 **먼 세 모서리**를 파도마다 로테이션.
  본진 코앞 모서리는 절대 안 쓴다 (준비 시간 없는 스폰은 불공정)

## 6. 파도 진입로 예고 (라운드 47 — 3D에서 더 중요해진다)

웹판은 다음 파도가 나올 모서리에서 본진 쪽으로 **큰 붉은 화살표**를 그린다.
파도 30초 전부터 뜨고 임박할수록 굵어진다.

쿼터뷰 3D에서는 화면 밖이 훨씬 많아지므로 **이게 더 중요하다.** 화면 밖
방향은 화면 가장자리에 핀으로 고정하는 처리가 추가로 필요하다.

## 8. 판단 시점에 다시 볼 것

PoC가 끝나면 **웹판을 지울지**를 결정하게 된다. 그때 이 표를 다시 볼 것:

| 자산 | 규모 | UE로 가면 |
|---|---|---|
| 시뮬레이션 (`shared`) | 4,811줄 | C++ 포팅 필요 |
| 테스트 (결정론·회귀) | 2,196줄 | 포팅 필요 |
| 렌더러·UI (`client`) | 5,234줄 | 폐기 |
| 서버 (lockstep 중계) | 1,101줄 | 대부분 폐기 |
| 2D 아트 | 101개 | 폐기 (3D 신규 제작) |
| **밸런스 수치·설계 (`docs/`)** | 48라운드 | **그대로 살아남는다** |

그리고 잃는 것 중 코드가 아닌 것:

- **웹 배포** — UE5는 웹 타겟이 없다. 링크로 폰에서 바로 하던 것이 사라진다
- **밸런스 하네스** — 864판 400초. 이걸 대체할 방법이 PoC에서 보여야 한다
- **자율 개발 루프** — 지금은 컨테이너에서 빌드·실측·E2E·커밋이 전부 자동이다.
  UE는 오너 로컬에서 돌아야 하므로 검증 왕복이 생긴다

> **웹판을 지우는 것은 PoC 성공과 별개의 결정이다.** 침공만 UE로 가고 1v1
> 대전은 웹에 남기는 길이 있고, 그러면 밸런스 하네스도 살아 있다.
