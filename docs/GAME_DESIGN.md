# 포밍뿌 로얄 — 게임 기획서

## 1. 한 줄 요약

**1v1 실시간 라인 전략.** 덱을 고르고, 엘릭서를 모아 카드를 아레나에 배치하고, 3분 안에 상대 타워를 더 많이 부수면 승리.

---

## 2. 핵심 루프

```
덱 선택 → 엘릭서 회복(자동) → 손패에서 카드 선택 → 배치 → 유닛이 자동으로 전진·교전
                       ↑                                              ↓
                       └────────── 타워 파괴 / 방어 성공 ←─────────────┘
```

플레이어는 **유닛을 조종하지 않는다.** 조종하는 것은 **무엇을 · 언제 · 어디에** 낼 것인가. 이 세 축이 게임의 전부다.

- **무엇을** — 상대 카드에 대한 카운터 선택
- **언제** — 엘릭서 우위(elixir advantage)를 만드는 타이밍
- **어디에** — 배치 위치가 유닛의 진행 레인과 교전 지점을 결정한다

---

## 3. 아레나

```
        x=0                x=9                 x=17
   y=0  ┌────────────────────────────────────────┐
        │        [적 킹타워 (9, 3)]              │   적 진영
   y=6  │  [적공주(3.5,6.5)]    [적공주(14.5,6.5)]│
        │                                        │
   y=15 ├══════════╗════════════════╔════════════┤  ← 강 (지상 유닛 통과 불가)
   y=17 ├─ 다리 ───╝                ╚─── 다리 ───┤     다리: x=3~5, x=13~15
        │                                        │
   y=25 │  [내공주(3.5,25.5)]  [내공주(14.5,25.5)]│   내 진영
        │        [내 킹타워 (9, 29)]             │
   y=31 └────────────────────────────────────────┘
```

- 그리드 **18 × 32 타일**
- 강이 맵을 반으로 가르고 **다리 2개**만 통과 가능 → 자연스럽게 **좌/우 2개 레인** 형성
- 배치 가능 구역: 기본은 **자기 진영**만. 상대 공주탑을 파괴하면 그 레인의 **적 진영 절반**까지 열린다 (역전 요소)

### 타워

| 타워 | HP | 공격력 | 공속 | 사거리 | 대상 | 비고 |
|------|-----|--------|------|--------|------|------|
| 공주탑 (2개) | 2400 | 90 | 0.8s | 7.5 | 지상+공중 | 파괴 시 왕관 1개 |
| 킹타워 | 4000 | 120 | 1.0s | 7.0 | 지상+공중 | **파괴 시 즉시 승리** |

킹타워는 **비활성 상태로 시작**한다. 공주탑이 하나 파괴되거나 킹타워가 직접 피해를 입으면 활성화된다.

**타워는 반드시 공중을 공격해야 한다.** 그러지 않으면 공중 유닛만으로 타워를 무한정 부술 수 있어 게임이 성립하지 않는다.

## 4. 엘릭서

- 최대 **10**, 시작 **5**
- **2.8초당 1** 회복 (틱당 고정소수점 가산)
- 경기 **마지막 60초는 2배속**
- 카드 비용은 2~5

엘릭서는 이 장르의 유일한 자원이자 실력의 척도다. "3코스트로 상대의 5코스트를 막았다" = **+2 엘릭서 우위** → 이 우위를 누적해 역공하는 것이 핵심 전략.

---

## 5. 덱

경기 시작 전에 **덱 하나를 고른다.** 덱은 8장으로 고정되어 있고, 배열 순서가 곧 순환 순서다.

- 손패 **4장** + "다음 카드" 1장 미리보기
- 카드를 내면 → 덱 맨 뒤로 → 다음 카드가 손패에 채워짐 (**순환 덱**, 셔플 없음)
- **앞 4장이 시작 손패**이므로, 덱을 설계할 때 앞쪽은 값싸고 방어적인 카드로 채운다

셔플이 아닌 순환 구조인 이유: 결정론적이고, 플레이어가 "다음 탱커는 언제 오는가"를 계산할 수 있어 **운이 아닌 실력 게임**이 된다.

두 플레이어가 서로 다른 덱을 고를 수 있다. 시뮬레이션은 처음부터 비대칭 덱을 지원한다 (`createState(seed, [deck0, deck1])`).

## 6. 공중 / 대공 — 이 게임의 두 번째 축

지상 전투만 있으면 "다리 앞에서 뭉쳐 싸운다"는 한 가지 상황밖에 나오지 않는다. 공중 유닛이 그 구도를 깬다.

**공중 유닛은**
- 강과 다리를 **무시하고 목표까지 직선으로 난다** → 레인 개념을 우회한다
- 지상 유닛·건물과 **충돌하지 않는다** (다른 층)
- `지상 전용` 공격에 **맞지 않는다**

**공격 대상 분류** (`targets`)

| 값 | 의미 |
|---|---|
| `any` | 지상·공중 모두 |
| `ground` | 지상만 — 공중을 때리지 못한다 |
| `air` | 공중만 — 대공 전용 건물 |
| `buildings` | 건물·타워만 — 유닛을 무시하고 직행 |

이 분류가 덱 구성에 강한 제약을 건다. **대공 수단이 하나도 없는 덱은 상대 공중 유닛에 아무것도 못 하고 진다.** 그래서 "모든 덱은 대공 수단을 최소 하나 갖는다"가 테스트로 고정되어 있다.

반대로 공중이 무적이 되지 않도록:
- 타워가 지상·공중을 모두 때린다
- 대공 전용 건물(`포자촉수`)은 사거리·화력이 지상용보다 세다

## 8. 승리 조건

1. **킹타워 파괴** → 즉시 승리
2. **3분 경과 시** 왕관 수가 많은 쪽 승리
3. 동점 → **연장전 60초**: 먼저 타워를 하나 부수는 쪽 승리
4. 연장전도 동점 → 무승부

## 9. 유닛 AI (플레이어가 조종하지 않으므로 여기가 "게임의 규칙")

매 틱, 각 유닛은 다음 순서로 행동한다:

1. **타겟 선정**
   - `targets` 분류로 때릴 수 없는 대상은 후보에서 제외한다
   - `건물만` 유닛이면 → 가장 가까운 적 건물/타워
   - 아니면 → 감지 범위(사거리와 5.5타일 중 큰 값) 내 **가장 가까운 적 유닛**
   - 없으면 → 가장 가까운 적 건물/타워
   - *동률이면 엔티티 ID가 작은 쪽* ← **결정론을 위해 필수**
   - 대공 전용 건물은 공중이 없으면 아무것도 타겟팅하지 않는다 (대기)

2. **사거리 안이면 공격**, 쿨다운이 0일 때 피해를 준다
   - 광역이면 대상 주변까지. 단 **지상 전용 광역은 범위 안이어도 공중을 때리지 못한다**

3. **사거리 밖이면 이동**
   - 지상: 목표가 강 반대편이면 먼저 **가까운 다리**로 향한다
   - 공중: 지형을 무시하고 **직선**으로 난다
   - 같은 층끼리 겹치면 서로 밀어낸다 (공중↔지상은 밀어내지 않는다)

이 단순한 규칙만으로 "탱커가 앞서고 딜러가 뒤따르는" 자연스러운 대형이 만들어진다.

## 10. 밸런싱 방법론

덱이 4개면 매치업이 **10개**(4개 미러 + 6개 교차)다. 손으로 감당할 규모가 아니다.

그런데 시뮬레이션이 **렌더링을 모르는 순수 함수**라 헤드리스로 대량 자동 대전이 가능하다. 카드 수치를 바꿔가며 매치업별 승률표를 뽑는 루프를 만들 수 있고, 이건 리플레이 저장(M4)과 같은 기반 위에 선다.

현재 수치는 **역할 구조에 맞춘 초기값**이지 검증된 밸런스가 아니다. 자동 대전 도구가 붙기 전까지는 그렇게 취급해야 한다.

## 11. 왜 이 게임인가 (기술적 관점)

| 항목 | 이 게임의 특성 |
|------|----------------|
| 동기화해야 할 데이터 | **입력(카드 배치)뿐** — 초당 1~2회, 수십 바이트 |
| 시뮬레이션 | 결정론적 lockstep → 양쪽이 같은 결과를 독립 계산 |
| 지연 민감도 | 낮음 (300ms 입력 지연을 게임 디자인으로 흡수) |
| 치팅 방지 | 서버도 동일 시뮬 실행 + 상태 해시 대조 |
| 확장성 | 카드 추가 = 데이터 테이블 한 줄, 덱 추가 = 카드 id 8개 |
